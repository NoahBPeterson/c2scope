# The tracing tools on cl 17.00 x64 (Visual C++ 2012 Update 4, x86_amd64): c2.dll 17.00.61030

Status: in progress. What works:

- the patched c2.dll loads the trace DLL, hooks and probes fire (on c2's worker threads too: section 2), the
  per-function filter works;
- `c2trace.py il` dumps the IL at any pass with operands, variable names, lines and encoded lengths;
- `tools/c2ncol.py` reports the x64 register allocator's decisions (`--why`: the priority formula per block;
  `--export`: the input of the model);
- `tools/ncolsim.py`, the model of that allocator: priorities 99% exact, register choice 96.9% (replay) / 94.7%
  (whole run from the traced start) on zlib; `whatif` predicts the registers after an appearance edit
  (docs/c2/ncolor.md 9);
- tsweep / bdiff / rdiff against x64 code (a disassembly of the original as the reference);
- `icount` (counts; the lift rules have a first x64 version: home-slot saves, register arguments);
- `tools/c2sched17.py`, the x64 scheduler (docs/c2/sched17.md): a per-region issue report and a replay model,
  1152 of 1173 zlib regions in exactly the traced order;
- `calleesum` on x64 executables (the Win64 convention; docs/c2/callee.md);
- `c2trace.py slots` (docs/c2/slots.md 6): the frame packer's colours, members and final rsp offsets, model exact
  on every function measured.
- `symkeys` (docs/c2/symkeys.md 10): keys, sites, events, whatif, compare, export; the replay reproduces every traced
  key (zlib 124411/124411), whatif predicted 855/857 keys and every pass-2 operand order on edited sources.

- `realize`, `rwsweep`, `helpersweep` predict with ncolsim on x64 (docs/c2/ncolor.md 10): appearances per block,
  declaration order (lifetime index), live counts; edits that change the block structure are measured, not
  predicted.

- From the IL (sched17.md 6.1, ncolor.md 11): `c2sched17 --predict` builds each region's DAG and static priorities
  from the IL (1155 of 1173 zlib regions in the traced order; alias answers still logged from the compiler);
  ncolsim `ilprio` / `ilsim` take appearances, ranges, blocks and depth from the IL (priorities 3182 of 3189).

Not yet: live counts per block and availability without a trace (section 6). On x64 there is no separate scratch-register
path: temporaries are NColor candidates, so c2ncol / ncolsim cover what `scratch` does on x86.

```sh
uv run tools/c2build.py setup --c2 17.00        # copies the compiler (work/vs2012/stage), patches c2.dll, builds c2trace.dll
uv run tools/c2trace.py il SRC --func F --c2 17.00 -- /O2
uv run tools/c2ncol.py SRC --func F --c2 17.00 -- /O2
```

## 1. The compiler

The x64 compiler of the free Visual C++ 2012 (Express for Windows Desktop, Update 4 or 5) is `VC/bin/x86_amd64`: a
**32-bit-hosted cross compiler**. cl.exe, c1xx.dll, c1.dll and c2.dll are PE32 (machine 0x14c), so the tracer's
entry-point patch and its 32-bit trace DLL carry over; what is new is the back end inside. **[C]**

| file | sha256 (prefix) | PDB |
|---|---|---|
| c2.dll | 0108f8b0d13bcf2b | c2.x86_amd64.pdb 21C28820E2994DDFB2C7B70BFA6D986C age 13 |
| c1xx.dll | 3e7583e8f17d51df | c1xx.x86_amd64.pdb 3B8D448328924D1D9F497A15ED877F12 age 1 |
| c1.dll | 9f52f46652eacaac | c1.x86_amd64.pdb 7C942F31AEE141BAB67ED2858339C222 age 1 |
| cl.exe | a9de754da92f18c9 | cl.x86_amd64.pdb 76106C9825EA4DE58E300327D738BC1B age 2 |

c2's PDB is public on Microsoft's symbol server (3,779,584 bytes): stripped, 9871 named functions, 18501 publics
with addresses, no types. Index: `work/index/17.00.61030-x64/c2.dll.csv` (`tools/pdbindex.py`). **[C]**

Patch: image base 0x10000000 (dynamic base: relocated under wine, 0x7ac10000 seen), 6 sections, .text file delta
0xc00, 356 bytes of .text slack from RVA 0x2e249c; the cave is at 0x2e24a0. c2.dll imports LoadLibraryW, not
LoadLibraryA: the cave passes the trace DLL's name in UTF-16 (`patch.loadlib = "w"`). A cross compiler builds DLLs
for its target, so c2trace.dll is compiled with the 14.00 x86 cl (`dll_build`). **[C]**

## 2. What is different inside

- **Compiler state is thread-local.** Per-function state (the current FUNC, the register tables, the allocator's
  arrays) is in c2.dll's static TLS block: `mov ecx,[__tls_index]; mov eax,fs:[0x2c]; mov X,[eax+ecx*4]`, then
  `[X+off]`. The trace DLL's specs take a new base **`tHEX`** (offset in the calling thread's TLS block; `set
  tlsidx`), and the function filter reads CurFunc from TLS (`set curfunctls`). CurFunc = TLS+0xdccc (written by
  dop2_GetInitialTuples), the function's front-end symbol = TLS+0xdd24. **[C]**
- **Tuples are C++ objects** (`class Tuple`, subclasses with vtables such as CodeAddrTuple) and every field moved;
  section 3. The dumper's offsets are now `set` variables (defaults = 14.00), kind numbers are mapped by `kind`
  lines.
- **Code generation runs on worker threads.** `DoMultithreadedCompilation` starts `WorkerThreadCount` workers
  (4 unless PGO or CLR forces 1), and each function's back end runs on one of them, so trace events of different
  functions interleave. c2trace.dll serializes its handlers (one lock), takes frames from one pool tagged with
  their thread, keeps the depth per thread, and writes `# thread N` when the logging thread changes (never before
  the first event: a single-threaded log is unchanged). `c2ncol.py` keeps one context per thread. **[C]**
- **The register allocator is new.** dop2_GlobalRegAlloc runs Globregs and then **NColor**; Color, Spillcosts,
  ChoosePhysReg and the local assigner RegSimpleAssignBody never run (a traced compile of a loop: none of them fired).
  NColor is about 250 functions (ncolor.obj, ncolormd.obj); docs/c2/ncolor.md. **[C]**
- **The opcode-name table has no pseudo-opcodes.** Opcode_name (0x100226e8) ends at `_last` = 0x4f5 (1270 machine
  opcodes). Pseudo-opcodes follow 15.00's order with insertions; names are carried over only for runs pinned by
  anchors (section 4).

## 3. IL layout (17.00 x64) **[C: read off traced tuples against the listing]**

| | 14.00 | 17.00 x64 |
|---|---|---|
| tuple: vtable / next / opcode | - / +0 / +4 | +0 / +4 / +8 (dword) |
| kind byte / flags byte (bit 0: instruction) | +8 / +9 | +0xc / +0xd |
| branch condition nibble | +0xa | +0xf |
| type word | +0xa | +0x10 (0x1004 int32, 0x1008 int64, 0x2004 uint32, 0x5008 double, 0xc010 / 0xe010 xmm, 0x9000 flags) |
| prev / owning BB / tuple number | | +0x18 / +0x1c / +0x28 |
| line word (offset from the function's line) | +0x14 | +0x20 |
| encoded length byte | +0x1c | +0x24 (EncSetOffsets reads and writes it) |
| src / dst operand lists | +0x28 / +0x2c | +0x30 / +0x34 |
| BLOCK tuple's BB | +0x20 | +0x28 |
| REG leaf: symbol / assigned register | +0x18 / +0x1c | +0x24 / +0x28 |
| memory leaf: symbol / base / index / disp / scale shift | +0x24 / +0x2c / +0x30 / +0x28 / +0x14&15 | +0x24 / +0x30 / +0x34 / +0x38 / +0x1c&15 |
| SYM: kind byte / number / name | +4 / +0x1c / [[+0]+4] | +8 / +0x20 / [[+4]+4] |

Kinds: leaves as in 14.00 (1 REG, 2/3 symbol, 4 code address, 5/6 memory, 7 ICONST); tuples one lower than 14.00
from the branch up (0x11 branch, 0x19 BLOCK, 0x1a LABEL), mapped in the table. SYM kinds: 1 register, 3 temporary,
4 variable. Register numbers (`?RegName@@3QBQBDB` 0x10001ff0): 1..16 rax..r15, 17..32 the 32-bit names, then 16-
and 8-bit, 144 xmm0, xmm0h/l/s variants; integer-vector xmm registers print as `ixmmN`.

## 4. Pseudo-opcodes

17.00 opcode = 15.00 opcode + 0x237 + shift, with the shift constant over runs:

| 15.00 range | shift | anchors |
|---|---|---|
| 0x2c0..0x2cf (ICONST .. INTERNAL) | 0 | the leaf kinds |
| 0x2d5..0x2e1 (ARG .. EXITSAVE) | 1 | ARG / ASSIGN / CONVERT / NEG shapes; ENTERLOAD 0x518 and EXITSAVE 0x519 tested in NColCanon |
| 0x2ec..0x318 (RET .. TUPLIST) | 5 | RET, ADD..XOR, DIV, REM, SHR, CMP, CALL, BRANCH, GOTO, SWITCH, INTRINSIC shapes in a test |
| 0x33d..0x340 (LABEL .. EXIT) | 0x1c | the tuple kinds |

The gaps (four pseudo-opcodes inserted between EXITSAVE and RET, 0x17 between TUPLIST and LABEL) print as `opNNN`
until they are pinned. **[C for the anchors]**

## 5. Hooks

Every function the 14.00 table hooks exists except the x87 allocator (FPColor, FPSpillcosts, FPRemoveSplitGlobregs,
MdmSuperHack), Spill and four scheduler/scratch helpers (CmdSetNextPos, CmdSubstDef, CmdUpdateCost,
CmdProcessBytePressure): 56 of 65. Pass order seen on a loop: dop2_PreLowerGlobalOpts, GrgIdentifyCandidates,
dop2_Codegen, dop2_GlobalRegAlloc (Globregs, NColor), dop2_CodegenFinish, Schedule, EncEmitFunc, Encode.

## 6. Not done

- Models without a trace: ncolsim still reads live counts, availability, preference windows and useable sets
  from the trace; c2sched17 reads the optimiser's alias answers (memory interference).
- The extended IL dump (`%+`); the Atom scheduler path; symkeys `levers` not measured against compiles.
- The levers on x64 do not predict block-structure changes, moved ranges or copy coalescing (ncolor.md 10);
  `realize pairs` is not ported; `--orig` / `--search` of slots read 32-bit code only.
- On x64 there is no RegAssign scratch path: temporaries are NColor candidates (c2ncol / ncolsim cover `scratch`).
