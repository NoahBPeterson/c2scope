# External rules, verified per build

Rules other projects found while matching, checked here with probe units on every build. The external file is
f3decomp's "Compiler rules for VS2005 SP1" (cl 14.00, 2026-11-19); its rule IDs (R###) are kept. Evidence tags:
[C] seen in c2's code or a trace here, [M] measured here with a probe (tests/data/rules/), [I] inferred, [ext] their
claim, not yet checked.

Status per build: **holds**, **differs** (and how), **n.a.** (the mechanism doesn't exist there), **?** (not run).

**How to add a rule probe** (T01):
1. Write `tests/data/rules/R<id>_<name>.cpp`: the external file's probe code where it gives one, plus variants
   selected with `/D` (or a cl switch such as `/arch:SSE2`), and a header comment naming the rule and the doc.
   Give each form its own function when one compile can hold them all (R1050 has 13 `x_*` functions).
2. Run it on all four builds before writing any expectation: `C2_BUILD=<b> uv run tools/msvc.py cl /c /O2 /TP /Gy
   /FAsc ...` for the listing (untraced, local), and for the deciding event a traced compile on the compile server
   with a function filter: `C2TRACE_FUNC='?f@@' uv run tools/c2trace.py --c2 <b> -H '<hook>' probe.cpp -- /TP`.
   Hooks by name work where the build has an index (`work/index/<build>/c2.dll.csv`); otherwise use a VA
   (`-H 1074b268=eax>0x99>0x50`), which is rebased with c2.
3. Add a check to your own test function in `tests/run_tests.py` (`rules_calls_tests`, `rules_misc_tests`,
   `rules_question_tests`). The helpers `rule_compile(name, *flags)` (listing text), `rule_proc(asm, prefix)` (one
   function's listing) and `rule_trace(name, func, hook, *flags)` (logged events) and the build key `RKEY`
   (`14.00`, `15.00`, `13.10.3077`, `13.10.3052`) are defined just before `rules_calls_tests`. Write the expected
   outcome as a dict keyed by `RKEY` with all four builds, even when they agree: `check(name, got, want[RKEY])`.
   A build that differs is expected to differ.
4. Add one row per rule ID to your section below (doc section, evidence, per-build status, mechanism, corrections),
   and document the confirmed rule in the subsystem doc with evidence tags.
