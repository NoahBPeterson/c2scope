# The tracing tools on the VC6 Processor Pack back end: c2.dll 13.0.9044

`c2trace` (`regs`, `scratch` with `--why`/`--export`, `il`, `slots`), `c2sched`, `regmap`, `realize` and `rasim` run
against c2.dll **13.0.9044**, the back end of Visual C++ 6.0 Processor Pack 5. It is the build `13.00.9044` of
`tools/c2builds/` (aliases `9044`, `13.00`, `vc6pp`); 14.00 stays the default and every other build's code path is
unchanged. This file records which binaries were used, how every address was found, what differs from 13.10, what
was measured and what is not ported. It is the third port after 13.10 (port-1310.md) and 15.00 (port-1500.md).

Tags: **[C]** confirmed (read in the 9044 code at the cited address, or seen in a 9044 trace), **[I]** inferred.
Addresses are RVAs; both 9044 and 13.10.3077 load at 0x10700000, so a VA is 0x10700000 + RVA.

## 1. Summary

- 9044 is a VC7-era back end behind the VC6 front end: its register allocator, slot packer and scheduler are 13.10's
  algorithms, with older data layouts, a fastcall internal convention and a Pentium (P5) scheduling model. **[C]**
- All 72 functions the 13.10 tools hook were located by reading the 9044 code (69 confirmed, 3 best candidates), plus
  the 3 functions of the slot packer; 74 mid-function probes were placed and checked (no overlapping or branched-into
  hook bytes). **[C]**
- Register allocation: `rasim check --predict` reproduces every decision column on 14 large zlib 1.2.1 functions and
  on 4 tests/data files with the 13.10 model, no per-build parameter (section 6). **[C]**
- Stack slots: the `slots` model reproduces 43 of 43 zlib functions and 6 of 6 tests/data/slots.c functions exactly,
  and every traced offset equals the listing's `_name$ = N` (223 of 223 named members). **[C]**
- Scheduler: rules 5 (height) and 6 (static priority, this build's `_SchmdHWT` row) hold on 7291 of 7291 nodes; the
  P5 pairing model added to `c2sched.py` (`sched_model: "p5"`) predicts 7289 of 7291 issue slots (section 5). **[C]**
- `scratch --why --export` and `rasim scratch`: the 14.00 pick rule predicts 7 of 7 picks and cursors of the
  regression function (RegBuildGlobalConflict's events 8-14 are ported). **[C]**
- `tests/run_tests.py` under `C2_BUILD=13.00.9044`: **157 of 157 pass**; 31 groups print a skip line, each with its
  reason from the table key `lacks` (section 7). **[C]**
- `symkeys` is ported (docs/c2/symkeys.md 11: replay 89403/89403 zlib keys; `keys --imm` for the immediate
  table that typedef-count dials act through).
- Not ported: the x87 view, the extended IL dump, `regs_imm`, `regs --pieces`, `origin`, the
  GlobalOptimize sub-pass hooks (icount), merges, loadcse's PAS dump, front-end passes (section 8).

## 3. Symbols and how functions were located

No PDB exists, so names come from 13.10.3077 (whose names come from the 13.10.6030 PDB, port-1310.md section 3):

| method | result |
|---|---|
| `tools/c2port.py match` 3077 → 9044 (`work/port1300/match9044.csv`) | 868 names: 697 functions (561 by call structure, 141 exact, 106 near, 30 signature), 171 data |
| Ghidra Version Tracking plus a token/structure correlator (`work/port1300/vt9044.csv`, `vt9044.md`) | 1522 function pairs (54% of 9044's 2807 functions; 208 from VT's own correlators), 1371 distinct function names, 187 data labels |
| reading (`work/port1300/hooks9044.md`, `.json`) | the 72 hooked functions: 69 confirmed, 3 best candidates, 0 absent; plus the slot packer's 3 |

Both matchers were hampered by 9044's layout: it is not BBT-scattered, but its cold blocks sit far from their
functions (0x73xxx-0x99xxx), so flow-following bodies were truncated in Ghidra and several automatic names are wrong;
every hooked function was therefore confirmed by reading its callers, callees and body against 3077's (the evidence
column of hooks9044.md). The pseudo-opcode numbers were carried over the same way: `work/port1300/opmap9044.py`
votes on the opcode constants compared or stored at `[reg+4]` in 100 matched function pairs (87 names in the table's
`opnames`). The machine opcodes are 0..0x246 (`opcount` 0x247, 3077: 0x24a). **[C]**

### 3.2 Mid-function probes

74 probes, all in `work/port1300/mktable9044.py` with a comment each. `work/port1300/hookchk9044.py` checks every

no branch may enter them past their first byte (two overlapping or branched-into hooks crash cl with C1001; the

### 4.1 The slot packer

ColorStackElements 4764f (fastcall: FUNC in ecx, the stack-symbol list in edx) and colorElemental 4855e are 3077's
algorithm; the colour record is **0x18 bytes** (3077: 0x1c): +0 members, +4 interference, +8 size, +0xc uses, +0x10
param offset, +0x14 alignment (no GS field: VC6 has no /GS). Globals: colours 107b15e8, count 107b15e4, params
107b15f4, LiveOnDef[] 107b15ec, stack-symbol count 107b15f8. SYM fields: index +0x38, size +0x20, uses +0x34,
alignment code **+0x54**. The 18 roles (c2slots.ROLES) are `hooks.slots`; gs_join / gs_new are null. The offset loop
counts down from the last colour in an ESP frame (and up in an EBP frame); its colour index is `[esp+0x10]` at
107479a4, not the loop count `[esp+0x24]`. Key `slots`: `sbv` {32 bits, next +4, 3 words}, `v13`, its own `sym`
template and `sorted` field names (ncol, T, ebp, nparams, cap). **[C]**

## 5. The scheduler on 9044

The DAG node layout and SchComputeStaticPriority are 3077's byte for byte (ready list 107b1b84/88/8c, `_SCHED_ccc`
107b1b60, `_issueArray` 107b1b74), so the six `sched` hooks are 3077's specs (edge probe 10714faa). Differences:

- **Static priority**: the `_SchmdHWT` row in use is (-1, 13, -5, -1, -2, 16, 16), the same as 3077's rows 0-2, so
  prio = ht << 13 + ns >> 5 + L << 16 (+ the x87-store term); table key `sched_hwt`. **[C]** (rule 6: 7291 of 7291)
- **Cost table**: SchmdInitialize's switch (ed9d) picks `_OpSchedInfo` 107b69b8 for its cases 2 and 3 (3077 86d29:
  108692e0); the trace reads 107b1a40 = 107b69b8, CPU row 2, `_Speed` 1, issue rate 2, 4 units. `opsched`
  ["107b69b8", "247"]: rows (latency, cost, pairing class). **[C]**
- **Selection (P5)**, `sched_model: "p5"` (c2sched.simulate_p5): each cycle fills up to 2 slots; for each slot
  SchSelectInstrs 15a7c walks the ready list (static priority descending, lex ascending: no dynamic priority while
  `_preSched` is 0) and takes the first node that passes SchmdGetFuncUnit 1075f249 (an fdiv waits on a 2-cycle flag;
  slot 0 needs units u and u+1 free, busy < 1; slot 1 needs SchmdPairable 1075f2ee with slot 0: classes 0 UV,
  0x100 U only, 0x200 V only, 0x300 not pairable; an x87 first instruction pairs only with fxch), SchmdCauseAGI
  15ce0, SchmdBadForFPSch 15d3e (under `_Speed`) and est <= cycle + max(busy, 0). An issue adds the cost to its
  unit (15e0d), every cycle subtracts 1 (15e87). Successors enter the ready list as soon as their remaining
  predecessors are only breakable ones (15a0b: DAGNODE +0x20 = +0x24), so a node added during the cycle may take
  slot 1 only after its predecessors issued. **[C]** except the AGI edge type, which the trace does not carry **[I]**.

## 7. tests/run_tests.py on 9044

`C2_BUILD=13.00.9044 C2TRACE_REMOTE=0 uv run python tests/run_tests.py`: **157 of 157 passed**, 31 skip lines.
A test skips when its feature is in the table key `lacks` (feature -> reason; `lacking()` / `skip()` in
run_tests.py); no other build has the key. The failures of the first run (66 checks, 18 crashes) were classified:

- **Fixed (port gaps)**: `scratch --why/--export` (scratch_x ported, 6 checks); the combined what-if compared the
  rows as a dict, which merges 9044's two `t162` globregs (now compared as a multiset); schedwant's replay used
  14.00's priority formula (now c2sched.HWT; identical for the other builds).
- **9044 expectations (genuine differences)**: f3's `--predict` columns (2/2, 3/3, 5/5, 46/46 where 14.00 has
  4/4, 4/4, 8/8, 45/45) and record numbers (26, 1/1, 2/2); realize2's ptrlocal lever (the base already reads p->q
  once); and, behaving as 13.10: realize2 eqa/eqb, realize_ins (both copies kept), alias2 (1 load), slots `/GS` (x
  in p's home: VC6 ignores /GS), icount's /fp hint (no /fp option).
- **Skipped, the VC6 tool chain lacks it**: /arch:SSE2 and emmintrin.h (fpclasses.c: XMM classes, regmap XMM/x87 rows,
  rasim need in the XMM pass); /GL and link.exe (LTCG, bdiff); `__declspec(noinline)` (realize.cpp, callnames.cpp,
  x87stack.cpp, ltcg_kill_b.c).
- **Skipped, not ported to 9044**: the x87 view, `regs --pieces`, immediate candidates (`regs_imm`), merges, loadcse (PAS dump), icount's pass attribution
  (GlobalOptimize sub-passes), front-end passes and Lower (probes feshape, il2c, lift), schedwant (its replay is
  single-issue without latencies), the twoaddr regmap test (its synthetic original assumes 14.00's code shape).
- **Skipped, not measured yet**: the rule probes (rules_calls / rules_question / rules_misc and probes frame,
  frontend, misc, opt, regalloc, regalloc_cost) have per-build expectation dicts without a 13.00.9044 entry.

- **IL dump**: the plain dump works at every pass; the extended dump (globreg view, member operands) is not ported.
- **Not in the table**: `regs_imm` (immediate candidates), `regs --pieces`, `origin` (where a temp without a pick got
  its register), the GlobalOptimize sub-pass hooks, merges' events, loadcse's PAS-index dump,
  front-end passes.
- **[I] items**: FgCoalesceLabels, FgCodeMotion and MdmSuperHack's addresses (call order only); regs event 4
  logs every register of the class list, including unavailable ones; the pref-23 and F16 probes can fire spuriously;
  the AGI edge type (section 5).
- The rule probes have no 9044 expectations (section 7).
