# c2 x87 code: FP globregs, GFx -> ST(i) mapping, and the x87 peepholes

This spec covers how cl 14.00.50727.762's back end (`Bin/c2.dll`) produces x87 code at /O2 for x86 (the default
`/arch`, so doubles and floats both use x87). It is meant for matching: given a function, predict which FP values
stay on the stack and in which slot, where `fld`/`fxch`/`fstp ST(i)` appear, and which operand becomes a memory
operand.

**[C]** = CONFIRMED (read in the code, and/or shown by a compile or trace; each claim says which). **[I]** = INFERRED.
Probes: `work/scratch/glass_x87/` (exploration `e*.c`, `t0.c`), `work/scratch/glass_x87/v/` (validation,
section 8), `work/scratch/glass_x87/peeps/` (peephole probes), `work/scratch/x87b/` (second round, section 8.1: k1-k13). Read docs/c2/regalloc.md first; class 1 below uses
the same colouring loop.

## Rules you can use when matching

1. **Read the GF form, then apply the mapper.** Every x87 instruction order is fixed by the IL that enters
   `X87MapGFxToSTx` (the "GF form": flat virtual registers GF0..GF7). Dump it with
   `uv run tools/c2trace.py il t.c --func _f --at @X87MapGFxToSTx@4,@FPPeeps@4,@LoFinalLower@4,@Schedule@8`.
   Given the GF form, rules 6-14 predicted the stack code exactly in all 12 validation probes. The hard part is
   predicting the GF form from the source (rules 2-5). **[C, compiles]**
2. **Evaluation order is decided by optimize.obj, not by the x87 code.** `OptLeftWeightTree` 10bb64b0 (called
   from `OptFuncExpr`) gives every node a 32-bit weight and merge-sorts the operand list of each `OPADD`, `OPMUL`,
   `OPAND`, `OPOR`, `OPXOR`, `OPEQ`, `OPNE` in descending weight (`OptCmpHashVal` 10bb6490; equal weights keep
   source order). `OPSUB`, `OPDIV` and **`OPCMP` (every `if (a < b)`, also `==`/`!=` in a condition) are not
   sorted.** After the sort the first operand is evaluated first, and for two memory leaves the first is the one
   loaded with `fld` and the second becomes the memory operand (`fmul QWORD PTR`). The weight is
   `SU << 24 | count << 16 | hash` **[C: code; probes k2, k5, k8, k10, k11 below]**:
   - **SU** (Sethi-Ullman need, `OptNodeComplexity` 10bb6670): 0 for a leaf; for an instruction, the first operand's
     SU, then for each later operand: one more if it equals the running value, its SU + 1 if it is larger. A call
     adds 7.
   - **count**: 1 for a variable or memory leaf, 0 for a constant (so constants always sort last and become the
     memory operand: `fmul __real@...`), and 1 + the operands' counts for an instruction.
   - **hash** (`OptHashNode` 10bb6720, 16 bits): named variable `32·key`; compiler temporary `64·key`; memory
     `[base+d]` = `d + (opcode − 0x274) + (hash(base) << 8)`; instruction = `Σ hash(opᵢ) << i` over the sorted
     operands, `+ opcode − 0x274`; all `& 0xffff`, so large keys wrap (a pointer param with key 8 gives its
     members the hash of a key-0 base: probe k2 G).
   - **A temporary with a single definition takes the weight of that definition** (in both functions: `sym+0x14`
     recursion). This matters for members: **a member at offset 0 is a plain memory leaf `[p+0]` (SU 0), but a
     member at offset d ≠ 0 is reached through an address temporary `t = p + d` and weighs as `OPADD(p, d)`: SU 1,
     count 2, hash `h(p) + 2·d + 0x31`.** So in `a->x * b->y`, `b->y` is loaded and `a->x` is the memory operand,
     whatever the keys; between two nonzero offsets the larger `h(p) + 2d` is loaded (k11: `a->v[1] * b->v[40]`
     loads `b`). Float→double conversions are such temporaries too, so they do not change the order.
   - **Keys** (`SYM.key`, il_sym.md; traced with `-H '@SymMakeUserVar@4=eax>4$/xeax>0x1c'`, probes k1, k3, k4):
     parameters first, **in reverse declaration order** (the last parameter is key 1), except that a member
     function's **`this` is key 1 and the declared parameters follow in reverse** (`m3(a,b,c)`: this 1, c 2, b 3,
     a 4); `__fastcall` register parameters are not special (all reverse). Then locals, in order of first
     reference in c1xx's IL. Globals take keys 32.. by first reference (left to right in the source). Temporaries
     64... An inlined callee's parameters get fresh keys after the caller's, but they are normally copy-propagated
     into the caller's own variables before `OptFuncExpr`, so **the caller's declarations decide**:
     `p.dot(q)` and `q.dot(p)` compile identically (k5).
   - Consequences: for two pointer parameters, the members of the **later-declared** pointer are the memory
     operands; in a member function, `this->m` is the memory operand against another pointer's member at the same
     offset (`x*o.x` loads `o.x`); among equal shapes the larger offset goes first (`x*o.x + y*o.y` computes the
     y product first); a global beats a parameter; a memory leaf beats a plain variable. To flip an order in a
     match, change the declaration order or copy into a local (higher key), not the expression's spelling.

   The same sort runs for integer expressions (it is optimize.obj, not x87 code). **[C]**
3. **A non-commutative node computes its heavier operand first.** If that is the right operand, `fsubr`/`fdivr`
   follows (`g1 - g2*g3` -> `fld g3; fmul g2; fsubr g1`). **[C, e4.c o12/o13]**
4. **Single-use locals are forwarded into their use.** They are not statements, so their computation moves to the
   use. A call operand is evaluated before the rest of the expression (`a*b + f(c)*a` calls f first).
   **[C, compiles: v/p11, e5.c mix]**
5. **Which FP values live on the stack across instructions:** the FP globregs. Color colours class 1 (FP) with the
   integer machinery (regalloc.md §3), and the default path does not use FPColor.
   - A param or variable needs benefit > 0, so in practice 2 or more references, to get a register. A single-use
     param stays a memory operand.
   - **At most 7 FP globregs are on the stack at once.** The 8th slot holds expression temporaries. With equal
     priorities, the values popped last lose: they stay in memory (`fld [src]; fstp home`, then `fadd home`
     later), or they get a short register piece and a home copy (`fst home`).
   - **Calls kill all of GF0..GF7.** A value live across a call is stored to its home before the call: `fstp` if
     the call argument push is the last register use, `fst` otherwise. After the call, one use stays a memory
     operand; two or more uses get a single `fld home`.

   **[C: regs report, compiles e2.c many, v/p5, e1.c callc, v/p4; the 7-limit mechanism is I]**
6. **Loads.** A globreg is loaded by `fld` where its first use is (the OPENTERLOAD is placed just before that use),
   not at function entry. A constant 0.0 becomes `fldz` and 1.0 becomes `fld1`. **[C: processFMOV_GFd_Mem
   10c31cd0, compiles]**
7. **Copies are free when the source dies.** `GFd <- GFs` renames the slot with no instruction. If the source stays
   live, the copy is `fld ST(i)`, and the new value is on top. Lower makes a copy for almost every two-operand op
   whose first operand is a live variable. (`v[1]*s`, with s a live globreg, is lowered as
   `fld v[1]; fld ST(k); fmulp`.) **[C: processFMOV_GFd_GFs 10c31650, compiles]**
8. **Binary ops on two stack values (fadd/fsub/fmul/fdiv): result into a dying slot, using a pop form where it
   can.** Let s1 and s2 be the sources.
   - (a) If neither is on top, `fxch` one to ST(0). The one chosen is s1, unless s1 stays live and s2 dies.
   - (b) Call the operand now on top T and the other O, at ST(k). If O dies: `fop[r]p ST(k),ST(0)`, and the
     result is left at ST(k-1). If O lives: `fop[r] ST(0),ST(k)`, and the result stays on top.
   - (c) The `r` (reverse) form is used exactly when the slot that receives the result held s2.
   - (d) The fxch is never undone. The permutation stays.
   - If s2 is memory: s1 is fxch'd to the top if needed, then `fop m`.

   **[C: X87StkRaiseAndMapSrcsToST0X 10c33100, processEgFADD 10c30700/FSUB 10c30870 with tables 10d099c0 and
   10d09a40, compiles]**
9. **Stores.** `mem <- GF` fxch's the value to the top if needed, and that fxch is not undone. It is `fstp` if this
   is the value's last use, `fst` otherwise. Storing one value to N places therefore gives `fst` N-1 times and
   `fstp` once, in a single run. PreMapping copy propagation and store regrouping make this happen even through
   temps. **[C: processFMOV_Mem_GFs 10c32000, PerformPreMappingPeepholes 10c2fb40, peeps probe st2]**
10. **Compares.** `OPCMP` keeps source order (rule 2). Lower makes `fcom L, R` with at least one operand in a
    register: **if both are in memory it loads the right one** (`_fmov t <- R`), otherwise it leaves them. The
    mapper raises the operands as in rule 8; if the right operand ends on top it swaps them and reverses the
    branch (`TupReverseCBranch`). Net effect for `if (a < b)`:
    - both in memory (single-use params, members, globals): `fld b; fcomp a` (k6 c6, k7 d1);
    - one side an expression: it is computed on the stack and the other side is the memory operand, on either
      side (k7 d7 `a <= b*c`: `fld b; fmul c; fcomp a`; d8 `a*c <= b`: `... fcomp b`);
    - a constant 0.0/1.0 on the right is loaded by `fldz`/`fld1`, any other constant on the right by
      `fld __real@...`, so the variable is the memory operand: `fldz; fcomp DWORD PTR [eax]` (k12);
    - both operands live on the stack (globregs): `fld b; fld a; fcom ST(1)` (v/p7, k6 c7).

    Floats: c1xx converts every float operand to double, and the two conversions of a float compare stay two
    loads, so **`if (p->x < q->y)` with two float operands is `fld [p]; fld [q+4]; fcompp`** in source order (also
    float params: k9 h2). Against a constant, the compare is narrowed back to float only when the constant is on
    the **right** (`p->x < 0.5f`: `fld DWORD __real@3f000000; fcomp DWORD [p]`); with the constant on the left it
    stays double (`0.0f < p->x`: `fld DWORD [p]; fcomp QWORD __real@0...`). A float against a double variable:
    `fld DWORD [p]; fcomp QWORD t` (k9 h4). **[C: IL at @Lower@4 and @dop2_PostLowerPreRegAllocGlobalOpts@4;
    probes k6, k7, k9, k12]**
    - The opcode comes from table 10d09ac0, indexed by `0x10` (`==`/`!=`: fucom family), `8` (right operand on
      the stack), `4` (it is ST(1)), `2` (top dies), `1` (right dies): `fcom`, `fcomp`, `fcompp` (both die,
      right at ST(1)), `fucompp` for `==`/`!=` on two stack values; with a memory operand `==`/`!=` use `fcomp m`
      (there is no `fucom m`). **[C table; k6 c3, k7 d5]**
    - **When the right operand dies but cannot be popped by the compare** (it is not at ST(1), or the top
      lives), table column 2 is set and `processEgFCOM` appends `fxch ST(i); fstp ST(0)` right after the
      `fnstsw ax`, which LoFinalLower folds to `fstp ST(i)`: `fcom ST(1); fnstsw ax; fstp ST(1); test ah,5`
      (k6 c7). Column 3 is used only by the `fucomi` (P6) rows. **[C code + k6 c7 IL at @FPPeeps@4/@Schedule@8]**
    - The flags then go through `fnstsw ax`, which LoFinalLower turns into `test ah,5 / 41h / 44h` + `jp/jne/je`.
11. **Block boundaries.** Blocks are mapped in a depth-first worklist. A join or loop header takes **the stack layout
    of the first predecessor mapped**.
    - After a two-way branch, the fall-through arm is mapped first, then (LIFO) the join.
    - A loop header takes the preheader's layout.
    - Each other predecessor gets an "airlock" block on its edge holding: `fstp ST(i)` for values dead on that edge
      (in GF-number order); `fldz` for values live in but missing; and fxch pairs that sort the stack into the
      fixed layout. The sort goes from the deepest slot up: `fxch ST(j)`, then `fxch ST(k)`, and an fxch with
      ST(0) is skipped.
    - Identical airlock fxch's at the head of both successors are hoisted above the branch by **`FgDoHeadMerge`
      10b2ef20 in `dop2_FinalFlowOpts` (FgDoLateFlowOpts mode 2)**, which runs after LoFinalLower and before
      Schedule, so no x87 peephole sees the merged code. Example: a loop's back-edge and exit-edge `fxch ST(1)`
      become one `fxch ST(1); jne` (v/p10: the only FgDoHeadMerge call in the compile). **[C trace]**
    - Values dead at a return are popped the same way (`fstp ST(1)` under the result).

    **[C: X87MapGFxToSTx 10c2eb00, FinalizeBlock 10c2f4e0, PropagateBlocksLiveOnExit 10c32550,
    BalanceBlockWithConstraint 10c2eef0; compiles e1.c ifj, e5.c j1, v/p3, v/p10]**
12. **Calls.** FP arguments are stored with `fstp [esp]` before the call, and the stack is otherwise empty. A double
    result arrives in ST(0). An unused result is popped. **[C: processCALL 10c310d0; compiles]**
13. **Float specifics.** Float and double share the 8 slots (GF0f..GF7f alias GF0..GF7). A `float` return value is
    rounded through memory: `fstp DWORD tv; fld DWORD tv`. LoFinalLower does not fold this pair for 4-byte values.
    `(int)x` calls `__ftol2_sse`, as a tail `jmp` when it is the return. **[C: compiles v/p2, v/p8, peeps p6]**
14. **Peepholes that change the visible code** (section 6). In order: FPPeeps, then LoFinalLower.
    - `fld ST(0); fop m` -> `fld m; fop[r] ST(0),ST(1)` (FldFp0FopMemPeep).
    - `fld m; fopp ST(1),ST(0)` -> `fop m`.
    - `fld ST(i); fopp ST(1),ST(0)` -> `fop ST(0),ST(i)`.
    - `fmul 2.0` -> `fadd ST(0),ST(0)`.
    - `fnstsw ax; sahf; jcc` -> `fnstsw ax; test ah,imm; jcc`.
    - `fxch ST(i); fstp ST(0)` -> `fstp ST(i)` (seen on the compare clean-up of rule 10, k6 c7).
    - Other rewrites exist (section 6) but never fired in about 70 probe functions.

    **[C: code + compiles]**
15. **The scheduler does not reorder x87 instructions among themselves.** It only moves integer instructions
    between them, adjusting displacements: `add edx,1` moved above `fld [edi+edx*8-8]`. **[C: FP sequence at
    @Schedule@8 entry equals the listing for v/p4, p5, p8, p10, e1.c; I that it always holds (every x87 op reads
    or writes ST registers, which serialises them)]**
16. **Flags.** `/TP /MT /GS /EHsc /Gy` (the game's flags) give identical x87 code to plain `/O2` C. **[C, v/p1, p6,
    p10]**

17. **A member read twice in one expression is loaded once, up front.** In `x*x + y*y + z*z` (an inlined
    `lensq()`), the three loads are value-numbered temporaries: all three `fld` come first, in the evaluation
    order of rule 2 (y, x, z), and each square is `fld ST(i); fmulp ST(i+1),ST(0)` except the last, which the
    fld-fopp peephole turns into `fmul ST(0),ST(0)`. **[C, k10 lensq; the hoisting point is I: it fits the
    temporaries' defs being placed at the first evaluation]**

## 1. Pipeline (default /O2, x86)

The `-QImapX87` bit (`_Module+0x44c & 0x8000000`) is set by default. **[C: trace on t0.c shows X87MapGFxToSTx
running and FPColor never called.]**

| step | where | what |
|---|---|---|
| 1 | `OptFuncExpr` (optimize.obj, in dop2_InitialOptsAndSetup) | rebuilds expression trees: sorts commutative operands and orders evaluation (rules 2-4). In e3.c the reorder is visible between the first and second OptFuncExpr entries **[C, il dump]** |
| 2 | `Lower` (lowerflt.obj: LfFPRegsPressure, LfFPCanonicalForm*) | x87 instruction selection in GF form: `_fmov`, `fmul GFd <- GFs1, GFs2/mem`, copies for live first operands **[C calls traced; details I]** |
| 3 | `Globregs` + `Color` (class 1) | FP variables become globregs and get GF0..GF7 in `_RegOrders[1]` order, first free wins. In Color 10b0d0xx, `FPPeeps`/`FPColor` are called only when FUNC+0xac&0x20 **and** the mapX87 bit is clear, so not by default **[C: decompile of Color at the call site, trace]** |
| 4 | `RegSimpleAssignBody` | temporaries get GFx; the GF number itself never reaches the output **[C trace; I that numbers are invisible except for tie order in rule 11]** |
| 5 | `X87MapGFxToSTx` 10c2eb00 (end of dop2_CodegenUpdate) | FgBuildFlowGraph, `PerformPreMappingPeepholes`, `BuildLiveOnEntryAndExitSets`, `SetGFxLifeAndDeath`, FgWeightFlowGraph, worklist of blocks (`ProcessBlock` + `FinalizeBlock`), rebuild flow graph, `PerformPostMappingPeepholes`, **`FPPeeps`** **[C decompile]** |
| 6 | flow opts (dop2_PostCodegenFlowOpts) | empty airlock blocks vanish; tail duplication of small joins (v/p3, e1.c) **[C compiles]** |
| 7 | `LoFinalLower` (dop2_CodegenFinish) | the x87 `try_*` peepholes of fppeeps.obj (section 6) **[C, peeps agent trace]** |
| 7b | `FgDoLateFlowOpts(2)` in dop2_FinalFlowOpts | `FgDoHeadMerge` hoists identical airlock fxch's above the branch (rule 11) **[C trace, v/p10]** |
| 8 | `Schedule` | integer instructions interleaved; FP order kept (rule 15) |

## 2. Which values are x87 globregs (class 1 in Color)

- `regs --all-classes` shows FP globregs as `[class 1]`, with candidates GF0..GF7 and every weight 0. The pick is
  therefore the first free GF in order. **[C, trace]**
- Priority and benefit follow regalloc.md §3.2 unchanged.
  - Example: f0 `a`, used twice in one block with P=3, has prio 2·2·3 = 12 and benefit 2·2 − 2 (enterload) = 2.
    **[C, trace t0.c]**
  - So a single-use param has benefit 0 and is spilled. It appears as `fop QWORD PTR _a$[esp-4]`. **[C]**
- Ties pop in defOrd order, as for integers. **[C, trace e2.c many: a..f popped first]**
- **7-value limit.**
  - In e2.c `many` and v/p5, ten values are live at once, and only seven (a..g) are ever on the stack together.
    The 8th slot always holds the temporary being loaded or stored.
  - InitialSplitPoints is called with k = 8 for class 1 (`_MaxPhysRegs[1]` = 8, traced). So the reservation is
    made elsewhere. **[C behaviour; mechanism I]**
- **Calls**: the call's kill set covers the GF registers. In e1.c `callc` and v/p4, `x` is stored before the call
  (`fst/fstp _x$`) and used from memory after it (one use) or reloaded once (two uses). **[C compiles; the kill set
  covering GF is I from the outcome]**
- **Differences from integer Color**: there is no register order to choose from (the GF number is a name only);
  the effective K is 7, not 8; and `ChoosePhysReg` weights are all 0, so preferences never matter. **[C trace; I
  for K]**

## 3. The mapper's stack model

`X87STK` sits at BLOCK+0xc0 (0x70 bytes) and is copied with `X87StkCopy` 10c328d0. **[C decompile]**

| off | meaning |
|---|---|
| +0x00..+0x1c | per GFx (0..7): its ST register number (0x2f = ST0, 0x30 = ST1, ...), or 0 if not on the stack |
| +0x20..+0x3c | per GFx: copy of the defining operand (compared by `X87StkEQ`) |
| +0x40..+0x5c | ring: physical slot -> GFx register; top-of-stack slot = (8 − depth) & 7 |
| +0x60 | depth |
| +0x68 | bit set of GFx on the stack (= BLOCK+0x128) |

Primitives: `X87StkPushGFx` 10c32ec0 (depth+1, every STi+1, new value at ST0); `X87StkPop` 10c32db0;
`X87StkSwap` 10c334c0 (fxch). Other BLOCK fields: +0xb4 live-in GF set, +0x124 live-out set, +0xbc "entry layout
fixed", +0x12c "mapped", +0x24 worklist link. **[C decompile; names I]**

**Death bits.** `SetGFxLifeAndDeath` 10c32630 walks each block backwards from its live-out set and sets
operand+0x15 & 0x10 on a source's last use and on a def that is never used. A dead def of an `_fmov` is deleted
(processFMOV 10c31330). **[C]**

## 4. Per-instruction mapping (ProcessBlock 10c30170)

`ProcessBlock` dispatches by opcode through the table at 10d08fe8 (processEgF*) and handles `_fmov`, call,
exitgoto, asm and sideeffect separately. **[C]**

### 4.1 `_fmov` (processFMOV 10c31330) **[C decompile + compiles]**

| form | output |
|---|---|
| `GFd <- mem` | `fld m` (push). 0.0 -> `fldz`, 1.0 -> `fld1` (MscFindFloatValue). If GFd still holds a stale value: `PrependKillGFx`, i.e. `fxch ST(i); fstp ST(0)` first |
| `GFd <- GFs`, s dies | rename, no instruction |
| `GFd <- GFs`, s lives | `fld ST(i)` |
| `GFd <- GFs`, d stale on stack | `fst ST(j)` (s lives) / fxch s to top, then `fstp ST(j)` (s dies) |
| `mem <- GFs` | fxch s to top if needed (kept); `fstp m` if s dies, else `fst m` |
| `GFd <- ST`, `ST <- GF` | the call result / return-value hooks |

### 4.2 Binary arithmetic (processEgFADD 10c30700, processEgFSUB 10c30870)

1. `X87StkRaiseAndMapSrcsToST0X(mode 1)` 10c33100. A is s1's slot and B is s2's.
   - s1 at ST0: nothing. s2 at ST0: swap the operand list, swapped = 1.
   - Neither on top: `PrependFxchSrc` brings s1 up, except that when s1 lives and s2 dies it brings s2 up and swaps.
   - s2 in memory: bring s1 up.
2. Index = swapped·8 + (s2 on stack)·4 + (new s1 dies)·2 + (new s2 dies). The table entry gives (action, swap-back).
   Action 2 = pop form; 3 = reversed form (`_f_opc_r`); 4 = reversed + pop.

   | idx | 5 | 6 | 7 | 13 | 14 | 15 |
   |---|---|---|---|---|---|---|
   | fadd/fmul (10d099c0) | swap | – | pop, swap | swap | – | pop, swap |
   | fsub/fdiv (10d09a40) | rev, swap | – | rev+pop, swap | swap | rev | pop, swap |

3. `X87StkMapSTxToGFxAndPop` maps the destination and pops if needed.

Worked out, this gives rule 8. Checked on every op in t0.c f0, e1.c, e5.c, v/p1, p3, p6, p11 and p12. **[C]**

Example (v/p1, `(a+b)*(a-b)`):

```
fld a            ; GF a                      stack: a
fld ST(0)        ; t = copy a (a lives)      t a
fld b            ; enterload b               b t a
fsub ST(1),ST(0) ; t-b: s2=b on top, lives  -> result in t's slot
faddp ST(2),ST(0); a+b: a renamed, b on top dies -> pop into a's slot     (a-b) (a+b)
fmulp ST(1),ST(0)
```

### 4.3 Compares, calls, others

- `processEgFCOM` 10c309e0: the raise mode is 1, or 2/3 with fcomi when `_Module+0x450 > 1`, i.e. a P6+ target,
  not the default.
  - A swap reverses the branch.
  - Table 10d09ac0 (16-byte entries): `fcom/fcomp/fcompp`; `fucom*` for opcode 0xd1; `fcomi*` for the P6 case.
  - Table entries are (opcode, uses fnstsw, remove dying s2 afterwards, fucomi parity fix-up); the index bits and
    the removal are in rule 10. **[C decompile + table dump + k6 c7]**
- `processCALL` 10c310d0: `X87StkOrderGFxSrc` puts GF sources (helper calls) into ST0.. order with fxch's and pops
  them. It pushes the FP result, or emits `fstp ST(0)` if there is none. **[C]**

## 5. Blocks, joins, loops

`X87MapGFxToSTx` loop **[C decompile]**:

```
worklist = InitializeFunctionBlockList()      // blocks with no preds, or no live-in GF and not airlocks
while b = pop(worklist):                      // LIFO via BLOCK+0x24
    b.stk = copy of b's fixed entry layout; ProcessBlock(b)
    FinalizeBlock(b):
        fldz for any live-out GF not on the stack (AppendFldZeroToBlock)
        for succ s with fixed layout: BalanceBlockWithConstraint(b, s)
        for succ s without: PropagateBlocksLiveOnExit -> airlock(b,s) with pops/fldz,
                            s.entry = airlock exit layout, push s
```

- `InsertConstraintAirLockBlockBetween` 10c2f790 always inserts a block on the edge (FgInsertAirlockBlock). Empty
  ones are cleaned up by the later flow passes. **[C]**
- `InsertExitToEntryAdjustments` 10c2f810 appends `AppendFstpGFxToBlock` (= `fstp ST(i)`, swap+pop) for each GF
  live out of b but not into s, then `fldz` for each GF live in but absent. Both loops go in GF order, GF0 first.
  This order is the one place where GF numbers are visible. **[C]**
- `BalanceBlockWithConstraint` 10c2eef0 runs from ST(depth−1) down to ST(1). At each mismatching slot k it calls
  `AppendFxchSTxToBlock(ST of wanted value)` and then `AppendFxchSTxToBlock(k)`, and fxch ST(0) is suppressed.
  **[C]**
- A self-loop whose exit layout differs from its entry is re-adjusted by PropagateBlocksLiveOnExit's `succ == b`
  case. **[C code; I effect]**

## 7. Fallout 3 cross-check (fn3-test, read-only)

The fn3-test log (0x007d30f0, a constructor) says plain float member stores were interleaved with the integer
zero stores, and that a run of 13 `fst` had to be kept intact by sub-object constructors.

- Rule 9 explains the run. One value (`fldz`) stored to N members is a single `fld`, then `fst` N−1 times and
  `fstp` once. This works through temps because of the PreMapping copy propagation and store regrouping.
- Rule 15 explains the interleaving. The scheduler keeps the fst run in order but is free to move the integer
  stores into it. Alias links (the sub-object constructors) are what pin the integer stores.
- The log's second lever is also consistent: an extern global used as the constant is reloaded for each store
  because a store may alias it. That is an IL fact.

**[I: consistent with the rules; not re-traced on the game function]**
